# scripts/

The pipeline that builds `out/` from `data/pt.txt.gz`. The top-level
[README](../README.md#how-the-list-is-built) describes what it does; this
file is for running and changing it.

## Running it

```bash
./.venv/bin/python -m scripts.build                 # release build -> out/, reports/
./.venv/bin/python -m scripts.build --stage 1       # April reconstruction -> build/stage1/
./.venv/bin/python -m scripts.build --sample 2000000   # dev run -> build/sample.../
./.venv/bin/python -m scripts.build --set fixes.plural_folding=false   # ablation
```

The release build exits with status 0. It exits 1 if the quality gate
finds a suspect that `config.yaml` does not accept; every output is still
written first.

Each pass is cached in `.cache/` under a digest of the settings that affect
it, so after the first build (about an hour, nearly all of it Stanza) a
change to a later stage reruns in about a minute. Only the release build
writes to `out/` and `reports/`; stage 1 and sample runs go to `build/`,
which is gitignored.

**Stage 1** reconstructs the lost April pipeline with every fix off and
simplemma alone. It reproduces its own earlier output byte for byte, and
the release report compares against it when `build/stage1/` exists.

Other entry points:

| Command | Does |
|---|---|
| `python -m scripts.counts --sample N --top 20` | Pass 1 only; prints the tokenizer fingerprint |
| `python -m scripts.eval_lemmas --backend stanza --backend gated` | Score lemmatizer backends against the gold set |
| `python -m scripts.make_whitelist --suspects reports/quality_suspects.tsv` | Classify quality suspects by the whitelist rule |
| `python -m scripts.make_proper_noun_review` | Merge new proper-noun drops into the review file, keeping decisions |
| `python -m scripts.fit_postag` | Regenerate `data/postag_rules.yaml` from the April release |
| `python -m scripts.make_glue_table` | Regenerate `scripts/data/enclitic_clusters.tsv` from the corpus |
| `python -m scripts.build_apkg` | Rebuild only the `.apkg` from the lists in `out/` |
| `python -m scripts.gloss --dry-run` | Gloss the 50-row stratified sample into `eval/gloss_dryrun.tsv` |
| `python -m scripts.gloss --estimate` | Count the input tokens a full gloss run would send; no glossing |
| `python -m scripts.gloss --rescue` | One corpus pass for the entries pass 2 never sampled; caches it and stops |
| `python -m scripts.gloss --submit` / `--collect` | The full gloss run, through the Batch API, into `out/glosses.tsv` |
| `python -m scripts.score_serir` | Score the ser/ir rule against both samples (development and held-out) and write the whole of `reports/serir_scores.md` |
| `python -m scripts.serir --score` | Development sample only; rewrites that report without the held-out table, and the `.json` the build checks |
| `python -m scripts.serir` | Draw a fresh ser/ir sample (refuses to overwrite labels) |

## Layout

| Module | Does |
|---|---|
| `build.py` | CLI entry point; runs every step, writes the reports, enforces the gate |
| `config.py` | Loads and validates `config.yaml`; output locations |
| `corpus.py` | Streams the gzip; never decompresses to disk |
| `tokenizer.py` | Artifact stripping, enclitic splitting with stem restoration, glued-cluster repair, sentence starts |
| `counts.py` | Pass 1: parallel unigram counts, fingerprint, cache |
| `bigrams.py` | Pass 2: bigram counts, sampled contexts, capitalization; Dunning G² |
| `lemmas.py` | Backends (simplemma, Stanza, gated, tiered, vote), overrides, closure |
| `occurrence.py` | The Stanza tagging pass; per-occurrence splitting of participles |
| `serir.py` | ser/ir next-word rule, its scoring, and its sample for the counts |
| `score_serir.py` | Scores the rule against both labeled samples into one report |
| `conventions.py` | The five conventions of `eval/conventions.md`, plus pronouns |
| `filters.py` | BP list, proper nouns and review decisions, foreign words, fragments, accent folding |
| `pos.py` | Published POS from tagger votes; consistency rule; POS splits |
| `postag.py` | Rule-based POS fallback |
| `emit.py` | Ranking, per-million, TSV/CSV/Anki writers |
| `build_apkg.py` | The `.apkg`: twenty 500-word decks from the band files (run by `build`) |
| `gloss.py` | English glosses and example sentences from the Anthropic API |
| `gloss_gates.py` | The gate on a finished gloss run, and `reports/gloss_gates.md` |
| `gloss_prompt.md` | The prompt they are written with; part of the method, not a comment |
| `quality.py` | Suspect duplicates, the gate, the fold listing |
| `compare.py` | `COMPARISON.md` |
| `eval_lemmas.py` | Gold-set scoring |
| `make_whitelist.py`, `make_proper_noun_review.py`, `fit_postag.py`, `make_glue_table.py` | Maintenance tools |

Hand-maintained data: `data/lemma_overrides.tsv` (verified lemmatizer
corrections), `data/postag_rules.yaml` (generated by `fit_postag`),
`data/quality_notes.md` (standing notes appended to `QUALITY.md`), and in
`../eval/` the gold set, conventions, gender pairs and proper-noun review.

## Things worth knowing

- **The `.apkg`'s note type and deck ids are fixed in `config.yaml`**
  (`output.anki.apkg`) and must never be regenerated, and note GUIDs come
  from lemma + POS; `tests/test_apkg.py` pins both. Changing either makes
  a re-import create duplicates instead of updating notes.
- **Human decisions live in `eval/`, not in code.** The gold set, the
  gender pairs, the proper-noun review and the gloss overrides each hold a
  reviewer's answer that beats the automatic one; regenerating tools merge
  rather than overwrite. `eval/gloss_overrides.tsv` is matched on lemma +
  pos and takes only the fields it fills in, so it can replace a gloss, an
  example, or both.
- **`pos` comes from Stanza's tags** (`pos.py`): a count-weighted
  majority vote, with a word split into one row per POS when a second POS
  is well supported (`pos:` in config). Tags that contradict their own
  lemma are discarded. The rule heuristic (`postag.py`, fitted to the April
  list) is only the fallback for entries with no usable tags, and the whole
  column in stage 1.
- **A clitic can be spelled like a tense infix.** `a` and `as` are in both
  `tokenizer.enclitics` and `tokenizer.mesoclitic_suffixes`, so
  `split_enclitic` only treats a peeled infix as mesoclisis when a clitic
  turned up to its left (`len(tail) > 1`). Without that test `conheço-a`
  reassembled into `conheçoa`, which reached the published list as a word.
- **Glued enclitic clusters come from a table, not a rule.** The corpus
  writes `deixa-me` and `deixame` both ways.
  `scripts/data/enclitic_clusters.tsv` lists the clusters where the
  hyphenated spelling is clearly the normal one and the glued one is not a
  word, not a verb form and not a capitalized name; `make_glue_table.py`
  generates it from a build with the repair switched off, so the table never
  depends on itself. Its digest is part of `cfg["tokenizer"]`, so every pass
  reruns when it changes.
- **Tried and rejected:** `fixes.cap_sentence_starts`, which excludes
  sentence-initial capitals from the proper-noun evidence. Numbers in
  `reports/QUALITY.md`. The code is kept behind the flag.
- **Stanza is not type-level.** One pass (`occurrence.py`) tags each
  frequent word in its sampled sentences -- 50 for forms with 10,000+
  occurrences, 5 otherwise -- and lemmas, splits and POS all come from it.
  The sample is fixed by digest rather than by a random seed, and a small
  sample is always a prefix of the large one.
- **The build reads the glosses but never writes them.** From 1.1
  `python -m scripts.build` reads `out/glosses.tsv` and
  `eval/gloss_review.tsv` to fill the deck and the enrichable TSVs, and it
  fails at the end if any published row has no gloss. It still never writes
  `out/glosses.tsv`: that comes from `scripts/gloss.py`, a separate run
  against the published lists, which needs `ANTHROPIC_API_KEY`
  in the environment (it is read from there and nowhere else, and a run
  without it aborts). Every raw response is kept in `cache/gloss/`, keyed
  by lemma + POS and stamped with the model, the prompt digest and the
  sentences that were sent, so a rerun re-sends only what changed. The
  model is never allowed to write Portuguese: it must return one of the
  corpus lines it was given, character for character, or nothing, and
  `gloss.verify` rejects the row otherwise. The leading dialogue dash and
  the quotation marks around a whole line are stripped for display, in
  `gloss.tidy`, **after** that check -- tidying first would let an edited
  sentence pass as verbatim.
- **Every published entry is glossed from real sentences.** Pass 2 samples
  lines for the 70,000 most frequent forms, and for a phrase only lines
  containing the whole phrase, which left nine entries with nothing;
  `gloss.scan_corpus` gives those one targeted corpus pass of their own,
  choosing lines by the same digest rule, cached like any other pass. The
  sentence filters relax in three tiers rather than hand an entry nothing:
  a word that only ever appears in shouted lines (`hmm`, `mayday`) is
  offered them, and the model may still decline to use one.
- **The tagger does not separate `ser` and `ir`**: it assigns `foi`/`fui`/
  `fomos`/`foram` to *ser* regardless of context. `serir.py` splits them
  instead: Stanza only decides whether an occurrence is a verb, and a
  next-word rule picks *ser* or *ir* over 1,000 random corpus lines per
  form (cached in `.cache/serir_*`). The build uses the rule only while
  `reports/serir_scores.json` shows at least `serir.min_accuracy` for the
  rule's current digest (its source plus the config lists it reads), so
  editing the rule means rescoring before a rebuild will apply it.
